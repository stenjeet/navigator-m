# Диагностика проблем

[English](../en/troubleshooting.md) | **Русский**

Это руководство описывает самые частые проблемы при сборке и запуске стека
Navigator-M. Начните с диагностики ниже, затем перейдите к разделу, который
соответствует наблюдаемому симптому.

## Первичная диагностика

```bash
cd ~/navigator-m
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 doctor
ros2 pkg list | grep navigator
ros2 node list
ros2 topic list
```

В каждом терминале всегда подключайте и дистрибутив ROS, и рабочее пространство.
Большинство проблем «пакет не найден», «неизвестный тип сообщения» и «топик не
найден» возникают в терминале, где не выполнен `source install/setup.bash`.

## Окружение и рабочее пространство

| Симптом | Причина | Решение |
|---|---|---|
| `ros2: command not found` | ROS не подключён. | `source /opt/ros/jazzy/setup.bash` |
| `Package 'navigator_bringup' not found` | Рабочее пространство не собрано или не подключено. | `colcon build --symlink-install` и `source install/setup.bash` |
| Неизвестен тип собственного сообщения | В терминале не подключено рабочее пространство с `navigator_interfaces`. | Выполните `source install/setup.bash` в этом терминале. |
| Команды работают только в одном терминале | У каждого терминала своё окружение. | Повторите обе команды `source`. |
| Неверный дистрибутив ROS | `ROS_SETUP` или окружение оболочки указывает на другой дистрибутив. | Используйте `/opt/ros/jazzy/setup.bash` или задайте `ROS_SETUP` явно. |

## Сборка

| Симптом | Причина | Решение |
|---|---|---|
| Сборка идёт крайне медленно | Рабочее пространство находится в `/mnt/c` в WSL. | Перенесите его в файловую систему Linux, например в `~/navigator-m`. |
| `colcon build` сообщает об отсутствующих зависимостях | Нет системных зависимостей или зависимостей ROS. | `rosdep install --from-paths src --ignore-src -r -y` |
| Изменения в Python-пакете не видны | Рабочее пространство собрано без символических ссылок. | `colcon build --symlink-install` |
| После правки кода поведение осталось старым | Всё ещё подключена старая установка. | Пересоберите и откройте терминал заново либо запустите `./run.sh`. |
| Предупреждения о метаданных `setup.py` | Метаданные пакета несогласованы. | Проверьте `package.xml` и `setup.py` в соответствующем пакете. |
| Сборка падает после смены дистрибутива ROS | В `build/` и `install/` остались артефакты другого дистрибутива. | Удалите `build/ install/ log/` и пересоберите. |

## Симуляция и топики

| Симптом | Причина | Решение |
|---|---|---|
| `/scan_ideal` или `/uwb/noisy_ranges` молчит | Симуляция не запущена. | Запустите `simulation.launch.py` или `./run.sh`. |
| Частота топика равна нулю | Узел упал или топик не публикуется в этой конфигурации. | Проверьте терминал launch-файла на исключения. |
| `/map/estimate` отсутствует | Картография не запущена или отсутствует `/estimate/odom`. | Запустите `mapping.launch.py` с `pose_source:=estimate` или `both`. |
| `/map/ground_truth` отсутствует | Картография работает без источника истинной позы. | Используйте `pose_source:=ground_truth` или `pose_source:=both`. |
| `/landmarks/observations` молчит | `landmark_node` не запущен. | Запустите `landmarks.launch.py` или `slam.launch.py`. |
| `/slam/odom` отсутствует | `ekf_slam_node` не запущен. | Запустите `slam.launch.py`; SLAM не использует `/estimate/odom`. |
| `/estimate/odom` отсутствует | Локализация не включена. | Запустите `localization.launch.py` или `simulation.launch.py use_localization:=true`. |
| TF `map -> base_footprint` не движется | `motion_node` не запущен или запрашивается не тот фрейм. | Проверьте `ros2 node list` и `tf2_echo map base_footprint`. |
| `NaN` в дальностях СШП | Пропуск — часть модели датчика. | Штатное поведение; фильтры пропускают `NaN`. |
| `inf` в лидарных дальностях | Отсутствие отражения — часть модели лидара. | Штатное поведение; картография игнорирует невалидные лучи. |

## RViz и графика

| Симптом | Причина | Решение |
|---|---|---|
| Окно RViz не открывается в Windows 10 | Нет X-сервера или WSLg. | Используйте `use_rviz:=false` или настройте X-сервер. |
| RViz открывается пустым | Неверно настроены Fixed Frame или дисплеи. | Загрузите `navigator_description/config/navigator.rviz`; Fixed Frame — `map`. |
| Модель робота не отображается | `robot_state_publisher` не запущен или URDF не разобрался. | Проверьте лог launch-файла и `/robot_description`. |
| Маркеры не отображаются | `/polygon_markers` не публикуется. | Запустите симуляцию или `display.launch.py`. |
| Дисплеи SLAM и ориентиров отключены | По умолчанию они выключены в RViz. | Включите соответствующие дисплеи вручную. |
| Нужен headless-скриншот | Дисплей недоступен. | Используйте Xvfb и `import` либо запустите с `use_rviz:=false` и сохраните данные инструментами. |
| RViz работает медленно | Слишком много дисплеев или большое облако точек. | Отключите неиспользуемые дисплеи и сократите историю сканов. |

## DDS и сеть

| Симптом | Причина | Решение |
|---|---|---|
| Узлы в разных терминалах не видят друг друга | Разные `ROS_DOMAIN_ID` или несовместимые реализации RMW. | Задайте одинаковые `ROS_DOMAIN_ID` и реализацию RMW в обоих терминалах. |
| Обнаружение ненадёжно в виртуальной машине или WSL | Ограничения multicast или межсетевого экрана. | Используйте одинаковый сетевой режим, проверьте правила межсетевого экрана или задайте `ROS_LOCALHOST_ONLY=1` для локальных запусков. |
| Связь работает локально, но не между машинами | Сеть или межсетевой экран блокируют обнаружение DDS. | Откройте нужные порты DDS или используйте discovery-сервер. |
| Старые узлы появляются снова | Предыдущий launch всё ещё работает. | Остановите его по `Ctrl+C` или командами очистки ниже. |

## Инструменты анализа

| Симптом | Причина | Решение |
|---|---|---|
| `run_visualize.sh` сообщает, что рабочее пространство не собрано | Нет каталога `install/`. | `colcon build --symlink-install` |
| Построение графиков падает на импорте | Не хватает Python-пакетов. | `sudo apt install python3-numpy python3-matplotlib` |
| `analysis.py` сообщает об отсутствии `/estimate/error` | EKF не стартовал или таймаут запуска слишком мал. | Проверьте лог запуска EKF и увеличьте `--startup-timeout`. |
| `map_compare.py` не находит карту | Картограф запущен без двух источников позы. | Используйте `pose_source:=both`. |
| Анализ как будто завис | Сценарии выполняются последовательно, каждый занимает десятки секунд. | Дождитесь строк состояния или используйте `--quick`. |
| `--replot` завершается ошибкой | Сохранённые данные `npz` отсутствуют или неполны. | Один раз запустите соответствующий инструмент без `--replot`. |
| Результатов нет в git | `results/` намеренно игнорируется. | Пересоздайте результаты локально; исходники и документация отслеживаются git. |

## Остановка и очистка

Останавливайте launch по `Ctrl+C`. Если после прерванного запуска остались
процессы:

```bash
pkill -9 -f lib/navigator_sim
pkill -9 -f lib/navigator_slam
pkill -9 -f /opt/ros/jazzy/lib/robot_state_publisher
pkill -9 -f /opt/ros/jazzy/lib/tf2_ros/static_transform_publisher
```

Удаляйте артефакты сборки только при необходимости:

```bash
rm -rf build install log
colcon build --symlink-install
```

## Логи и диагностика

- Вывод launch-файла печатается в терминал; исключения обычно появляются в
  первые секунды.
- `ros2 node list` показывает, какие узлы действительно запустились.
- `ros2 topic info <topic> -v` показывает издателей, подписчиков и QoS.
- `ros2 topic hz <topic>` и `ros2 topic echo --once <topic>` подтверждают поток
  данных.
- `ros2 run tf2_ros tf2_echo map base_footprint` проверяет цепочку
  преобразований.
- `ros2 doctor --report` печатает подробный отчёт об окружении.
