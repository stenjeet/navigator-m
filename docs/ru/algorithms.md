# Алгоритмы

[English](../en/algorithms.md) | **Русский**

В этом документе описаны алгоритмы оценивания и построения карты, которые
использует рабочее пространство. Все модули написаны на чистом Python и покрыты
unit-тестами.

## Обозначения

- `mu`, `x` — оценка состояния.
- `Sigma`, `P` — ковариация состояния.
- `F`, `H` — якобианы процесса и измерения.
- `Q`, `R` — ковариации шума процесса и измерения.
- `z` — вектор измерения.
- `dt` — шаг прогноза.
- `v`, `omega` — заданные линейная и угловая скорости.

## EKF-локализация

Модуль: `navigator_localization/ekf.py`, ROS-обёртка: `ekf_node.py`.

### Состояние и прогноз

Фильтр оценивает плоскую позу `base_footprint` в `map`:

```text
mu = [x, y, theta]^T
```

Прогноз использует дифференциальную модель движения и заданные скорости из
`/cmd_vel`:

```text
x     += v * dt * cos(theta)
y     += v * dt * sin(theta)
theta += omega * dt
```

Якобиан процесса равен

```text
F = [1, 0, -v * dt * sin(theta)]
    [0, 1,  v * dt * cos(theta)]
    [0, 0,        1           ]
```

а ковариация пересчитывается как `P = F P F^T + Q`.

### Коррекция по СШП

Для якоря `(ax, ay, az)` и смещения метки `(dx, dy, dz)` в `base_link` позиция
метки в `map` равна

```text
tx = x + dx * cos(theta) - dy * sin(theta)
ty = y + dx * sin(theta) + dy * cos(theta)
tz = dz
```

Предсказанная дальность — это 3D-расстояние до якоря:

```text
r = sqrt((tx - ax)^2 + (ty - ay)^2 + (tz - az)^2)
```

Строка якобиана измерения имеет ненулевые элементы только в блоке робота:

```text
H = [ (tx - ax) / r, (ty - ay) / r, dr/dtheta ]
```

`dr/dtheta` учитывает поворот смещения метки. Некорректные дальности и `NaN`
отбрасываются до пакетного обновления. Каждое обновление использует форму
Джозефа

```text
P = (I - K H) P (I - K H)^T + K R K^T
```

которая сохраняет `P` симметричной положительно полуопределённой, и приводит
курс к интервалу `(-pi, pi]`.

### Наблюдаемость

Одна СШП-метка в статике ограничивает только положение метки. Курс не
наблюдается по одним дальностям, поэтому он корректируется движением и
поворотами. Это физическое свойство модели, и оно покрыто отдельным тестом.

## Сетка занятости

Модуль: `navigator_slam/occupancy_grid.py`, ROS-обёртка:
`occupancy_grid_node.py`.

### Обновление в лог-оддсах

Каждая ячейка хранит занятость в лог-оддсах:

```text
l = log(p / (1 - p))
```

Для каждого валидного луча ячейки вдоль луча получают свидетельство
свободности, а конечная ячейка — свидетельство занятости:

```text
hit  : l += log(p_occupied / (1 - p_occupied))
free : l += log(p_free     / (1 - p_free))
```

Результат ограничивается интервалом `[log_odds_min, log_odds_max]`, поэтому
старое свидетельство всё ещё можно перевесить, и ни одно измерение не
доминирует навсегда.

### Трассировка луча

Луч сэмплируется с шагом `resolution / 2` (по умолчанию половина ячейки).
Затронутые ячейки дедуплицируются, а трассировка векторизована по всем лучам.
Ячейка, в которую попал один луч и которую лишь пересёк другой, считается
занятой для этого скана.

### Публикация

Лог-оддсы переводятся обратно в вероятность и сравниваются с порогами:

| Выход | Условие |
|---|---|
| `100` занята | `p >= occupied_threshold` |
| `0` свободна | `p <= free_threshold` |
| `-1` неизвестна | иначе |

Сетка по умолчанию покрывает `-0.5..8.5 m` по обеим осям с ячейками `0.05 m`,
что даёт `180 x 180` ячеек.

### Сравнение карт

`tools/map_compare.py` сравнивает две сетки по:

- IoU занятых ячеек;
- согласию среди ячеек, известных в обеих картах;
- среднему и максимальному расстоянию от занятых ячеек одной карты до
  ближайшей занятой ячейки другой;
- количеству ячеек, занятых только в одной карте.

Расстояние — основная метрика: тонкие стены и ориентиры занимают одну-две
ячейки, поэтому IoU очень чувствителен к сдвигу на одну ячейку.

## Детектор ориентиров и ассоциация

Модуль: `navigator_slam/landmark_detection.py`, ROS-обёртка:
`landmark_node.py`.

### Сегментация скана

1. Каждый конечный луч в пределах `[min_range, max_range]` становится точкой в
   `base_footprint`. Смещение лидара добавляется к конечной точке луча.
2. Скан разбивается там, где скачок дальности превышает
   `jump_threshold + |angle_increment| * mean_range`.
3. Короткие разрывы из невалидных лучей сшиваются, а первый и последний
   кластеры объединяются через границу кругового скана на 360 градусов.

### Проверка окружностью

Кластер принимается, когда:

- в нём `min_points..max_points` лучей;
- его ширина меньше `max_cluster_width`;
- окружность радиуса из `radius_min..radius_max` описывает его с радиальным
  СКО остатка ниже `max_residual`.

Короткие дуги плохо обусловлены для алгебраического подбора окружности методом
наименьших квадратов, поэтому детектор переходит к подбору дуги по хорде и
стрелке. У плоской стены стрелка почти нулевая, поэтому подобранный радиус
становится очень большим, и кластер отбрасывается. Окно радиусов отсекает
цилиндры 0.30 м и 0.42 м, а ограничение ширины — стены и препятствие-коробку.

### Ковариация наблюдения

Для `n` точек, радиального остатка `res` и полушрины кластера `h`:

```text
range_variance   = (sigma_range^2 + bias^2) / n + res^2 + h^2
bearing_variance = sigma_bearing^2
                   + (sigma_range^2 + bias^2) / (n * range^2)
                   + angle_increment^2 / 12
```

Член `h^2` учитывает неопределённость центра короткой дуги.

### Ассоциация

Наблюдения сопоставляются с известными ориентирами по махаланобисову
расстоянию дальности и азимута. Гейт — порог хи-квадрат для двух степеней
свободы (`9.21` для 99 %). Ассоциация жадно идёт по наименьшему расстоянию, и
каждый ориентир и каждое наблюдение используется не более одного раза за скан.
Несопоставленные наблюдения получают новый id.

### Подтверждение кандидатов

Кандидат попадает в карту только после `min_hits` согласованных наблюдений в
пределах `tentative_gate`. Настоящий ориентир наблюдается сотни раз, а угол
стены, подогнанный как маленькая окружность, появляется лишь несколько раз.
Буфер кандидатов ограничен `max_tentative_tracks`.

## Совместный EKF-SLAM

Модуль: `navigator_slam/ekf_slam.py`, ROS-обёртка: `ekf_slam_node.py`.

### Состояние

Совместное состояние содержит позу робота и все ориентиры:

```text
mu    = [x, y, theta, m1x, m1y, ..., mNx, mNy]
Sigma = cov(mu)                       # (2N + 3) x (2N + 3)
```

Кросс-корреляции между роботом и ориентирами — это то, что превращает повторно
наблюдаемый ориентир в поправку позы (замыкание петли).

### Прогноз и коррекция по СШП

Прогноз — та же дифференциальная модель, что в EKF-локализации, но с полным
якобианом процесса. `Q` ненулевая только в блоке робота; блоки ориентиров
растут через кросс-ковариации. Коррекции по СШП переиспользуют модель
дальности из EKF-локализации, включая смещение метки и обработку пропусков.

### Коррекция по ориентиру

Для ориентира в `(mx, my)` предсказанное наблюдение равно

```text
d     = hypot(mx - x, my - y)
alpha = wrap(atan2(my - y, mx - x) - theta)
h     = [d, alpha]
```

Якобиан имеет ненулевые блоки для позы робота и связанного ориентира.
Обновление ковариации использует форму Джозефа.

### Инициализация

Новый ориентир инициализируется обратной моделью наблюдения при текущей позе
робота:

```text
mx = x + range * cos(theta + bearing)
my = y + range * sin(theta + bearing)
```

Новый блок и его кросс-ковариации со всем состоянием заполняются из якобиана
робота, поэтому последующие наблюдения других ориентиров сохраняют корректные
корреляции. Диагональ ограничена снизу значением `initial_landmark_std^2`.

### Ассоциация и подтверждение

Ассоциация использует совместную ковариацию инновации (блок робота, блок
ориентира и кросс-члены) плюс модельный минимум ковариации детектора. Кандидат
попадает в совместное состояние только после `min_landmark_hits` согласованных
наблюдений в пределах `tentative_gate`. Это не даёт углам стен превращаться в
фантомные ориентиры.

### Замыкание петли

После замкнутой траектории те же ориентиры наблюдаются повторно. Их
кросс-корреляции обновляют позу робота и уменьшают дрейф. Unit-тест
`TestLoopClosure.test_double_loop_closes_and_keeps_the_ids` выполняет два круга
и проверяет, что остаются четыре id и дубликаты не появляются.

## Сценарный анализ

Модуль: `tools/analysis.py`.

Инструмент генерирует альтернативные файлы `sensors.yaml` и `ekf.yaml` для
списка сценариев, запускает стек картографии без графики, записывает
`/estimate/error` и итоговые сетки занятости, а затем агрегирует:

- RMSE положения и курса;
- максимальную абсолютную ошибку позы после окна прогрева;
- IoU занятых ячеек;
- среднее расстояние между оценённой и эталонной картами.

Встроенный профиль покрывает уровни шума СШП, рассогласование фильтра и модели,
пропуски, окно отказа СШП и альтернативные раскладки якорей. Шум лидара в
профиле по умолчанию фиксирован.
